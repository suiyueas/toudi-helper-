<h1 align="center">toudi-helper-</h1>

基于 Tampermonkey（篡改猴）的全平台自动求职投递脚本。支持 **BOSS 直聘**、**智联招聘**，内置智能关键词评分（过滤全栈/销售等坑岗）、自动打招呼、自定义文本及数据导出，帮你高效海投。

> ⚠️ 本脚本仅供个人求职效率工具使用，请遵守目标招聘平台的服务条款，控制投递频率，风险自负。

## 功能特性

- **多平台支持**：BOSS 直聘、智联招聘，数据完全隔离，互不干扰。
- **智能评分筛选**：
  - 正面/负面关键词打分，岗位名与技能命中额外加权；
  - 长词优先去重（`Java` 与 `Java后端` 对同一段文字只计一次，不再叠分）；
  - 岗位名直接含负面词硬否决（不看分数直接跳过）；
  - **强正面证据放行**：正面得分（未扣负面分）达到中分阈值且命中 ≥3 个正面词时，正文里零星的负面词不再否决（岗位名负面词仍然硬否决）；
  - 核心词必中、否定上下文识别（如"不招运维"不计分）；
  - 可选 OpenAI 兼容接口做语义评分（-10 ~ +20）。
- **多维过滤**：城市允许/禁止列表（禁止命中直接跳过，优先级更高）、薪资区间、公司筛选/黑名单、公司已投递去重（跨批次）。
- **跨批次去重**：跳过历史已沟通岗位（读取本地 IndexedDB 索引，刷新后依然生效）。
- **节奏与风控**：每日投递配额（按自然日累计，跨运行生效）、连续失败指数退避（30s→300s）、模型评分连续失败自动熔断。
- **自动投递主流程**：列表选岗 → 点击沟通 → 聊天页发送问候语/自定义文本 → 返回列表继续，随机时间间隔防检测。
- **暂停后续扫**：因弹窗/受限暂停后改完参数再点启动，直接从暂停处继续（同一筛选列表才续扫，换城市/筛选会自动从头）。
- **弹窗处理**：沟通次数提醒自动确认，硬限制自动暂停。
- **数据管理**：岗位沟通记录导出（JSON/CSV）、一键清理、运行统计与 7 日趋势。
- **右侧控制面板**：全部参数可视化配置，实时日志、评分结果与状态提示。

## 安装

1. 安装浏览器扩展 [Tampermonkey（篡改猴）](https://www.tampermonkey.net/)。
2. 点击下方按钮安装脚本（或将 [`toudi-helper-.user.js`](./toudi-helper-.user.js) 内容复制到 Tampermonkey 的"添加新脚本"中保存）：

   [![Install](https://img.shields.io/badge/安装-用户脚本-brightgreen)](./toudi-helper-.user.js)

3. 打开 [BOSS 直聘](https://www.zhipin.com/) 或 [智联招聘](https://www.zhaopin.com/) 的岗位列表页，右上角会出现脚本控制面板。

## 快速上手

1. 打开面板 → **评分筛选**，填写正面关键词（如 `Java,Spring,后端`）与负面关键词（如 `销售,直播,客服`）。
2. 按需勾选城市、薪资、黑名单等过滤条件。
3. 在 **运行策略** 中设置随机间隔、最大沟通数，按需勾选「跳过历史已沟通岗位」。
4. 点击 **开始**，脚本会自动筛选、沟通并记录；面板可随时暂停/停止。
5. 运行结束后在 **数据** 页导出沟通记录。

### 推荐评分参数

| 参数 | 建议值 | 说明 |
|---|---|---|
| 正面权重 | 8 | 每命中一个正面词加分 |
| 负面权重 | 40（默认）~60 | 去重后每个负面词只扣一次；调太高会把"正文顺带提词"的好岗位拖成低分 |
| 岗位名加权 | 12 | 正面词出现在岗位名时额外加分 |
| 技能加权 | 6 | 正面词出现在技能标签时额外加分 |
| 负面·岗位名扣分 | 40 | 负面词出现在岗位名时额外扣分 |
| 高分阈值 | 70~80 | 达到即 good，直接投递 |
| 中分阈值 | 30~40 | 达到即 mid，直接投递 |
| 核心词必中 | `java,spring` | 岗位需命中其一才投，留空不启用 |

> 面板配置保存在浏览器 localStorage，改代码里的默认值对已保存的配置无效，请直接在面板中修改。

## 数据存储

| 存储 | 位置 | 用途 |
|---|---|---|
| 岗位沟通记录 | IndexedDB（按域名隔离） | 历史记录、导出、已沟通索引 |
| 运行状态 | localStorage | 页面跳转/刷新后恢复自动化状态 |
| 面板配置 | localStorage | 全部可调参数 |
| 已投递公司名单 | localStorage | 跨批次公司级去重 |

清空浏览器数据会同时清空以上记录，重要数据请先在"数据"页导出。

## 开发

改动流程（需要 Node.js）：

1. 编辑 `src/` 下对应模块（如 `src/11-automation.js`）。
2. 运行 `node tools/build.js`，重新生成 `toudi-helper-.user.js` 并自动做语法校验与逐字节往返校验。
3. 把生成的 `toudi-helper-.user.js` 全量复制进 Tampermonkey 保存，刷新页面生效。

补充说明：

- `node tools/split.js` 是一次性工具，把完整脚本按 `tools/parts.js` 的锚点重新拆进 `src/`；日常只需 `build.js`。
- 锚点必须是文件中唯一的整行，拆分/构建都依赖它定位；改动如影响锚点需同步更新 `tools/parts.js`。
- 生成产物与 `src/` 拼接结果逐字节一致，可放心用 diff 对比。

脚本内部主要模块：

- `RunState` — 跨页面状态机持久化
- `JobRepository` — 岗位数据归一化与匹配
- `Database` / `ContactedIndex` — IndexedDB 存储与已沟通索引
- `ScoreService` — 关键词评分与等级判定
- `FastReplyService` / `GreetingService` — 常用语与自定义文本发送
- `Automation` — 投递主流程（列表 → 聊天 → 返回）
- `Exporter` / `RecordCleaner` — 记录导出与清理

## 常见问题

- **脚本不显示面板**：确认已启用脚本，且当前页面 URL 与 `@match` 规则匹配。
- **改了代码不生效**：需在 Tampermonkey 中重新保存脚本并刷新页面。
- **提示未登录**：先在目标站点登录账号再启动。
- **频繁跳过岗位**：检查评分阈值是否过高、核心词是否过窄，参考上文推荐参数。
- **暂停后重启会从头扫吗**：同一筛选列表会从暂停处继续（状态栏显示"已处理 N 个岗位"）；**手动点"停止"后再启动也一样从停止处继续**（自动停止如"达到上限/列表已扫完"仍从头开始）；换了城市/搜索条件则自动从头开始。
- **面板在哪里显示**：岗位列表页、BOSS 首页显示；**BOSS 消息界面（聊天页）不再显示**助手面板——脚本仍在后台完成发消息与返回列表，回到岗位列表页会自动恢复。
- **投递时手动打开消息界面，助手会停吗**：不会。扫描会挂起等待（状态栏提示"已离开岗位列表"），切回岗位列表页自动继续，不需要重新点启动；也不会误判"列表已扫完"去刷新页面。
- **日志条数涨得太快/徽标总显示 99+**：实时日志默认只记结论事件（每个岗位的通过/跳过、发送成功、警告错误），扫描、接口抓取、进聊天页、切换等待等过程事件不再刷屏；需要逐条过程排查时，打开日志页的「记录」调试日志开关即可全部显示。
- **日志是英文/想要中文**：日志页右上角按钮显示"人易读"说明当前是机器格式（原始事件名+JSON），点一下切成中文人易读格式；新版本已默认中文并重置了旧的格式偏好。
- **日志级别筛选是什么含义**：「信息」= 正常结论（岗位通过/跳过、发送成功）；「警告」= 需要留意但不中断（连续失败、沟通达上限、离开列表暂停）；「错误」= 真正的失败（发送失败、按钮未找到、登录失效）。岗位跳过属于正常结论，不出现在「错误」里。
- **岗位被“评分跳过”但不知道为什么**：数据页记录行上直接显示拒绝原因（如“命中反面词：销售（正面 52 − 负面 60 = −8）”），导出 CSV 的“拒绝原因/正面分/负面扣分”列同样有。
